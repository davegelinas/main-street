# Upgrading a site made before October 2026

Sites made before the October 2026 update use a `staging` branch, a private repository, and an analytics token. Each site carries its own copy of the rules, so nothing changes until someone upgrades it on purpose. Give the owner's AI this page and say "upgrade my site using this."

**AI doing the upgrade:** do it as one pull request with a preview link, like any other change, and confirm each GitHub or Cloudflare setting with the owner as you go. Since Phase 1 (late 2026) the template runs on Cloudflare Workers, not Pages: after these steps, do "Moving a Pages site to Workers" below.

1. **Copy the new manual and rules** from this toolkit's `template/`: `AGENTS.md`, `CLAUDE.md`, `SETUP.md` (tick everything that's already done), `rules/`, and the owner docs in `docs/`. Keep the site's own words, `site.config.json`, and `content/`.
2. **Copy the new machinery:** everything in `plugins/` (`site-config.ts`, `share-image.ts`, `icons.ts`, and `monogram-glyphs.json` with its license), `scripts/`, `src/`, `wrangler.jsonc`, `.dev.vars.example`, `public/_headers`, `public/fonts/`, `public/favicon.svg`, `public/favicon-32.png`, `public/apple-touch-icon.png`, the page `.html` files' `<head>` changes, and `package.json` + `package-lock.json` (adds `sharp`). Delete `functions/_middleware.ts`. Leave `.github/workflows/ci.yml` out of this pull request: many cloud AIs can't push workflow files, and a refused push refuses everything. Add it separately the way `AI-SETUP.md` steps 5 and 7 describe (try it as its own commit; if refused, send the owner the one-tap link).
3. **Remove the old analytics beacon** from `index.html` (the `<!-- feature:analytics -->` block containing `{{analyticsToken}}`), and wrap the canonical and `og:` tags in `<!-- feature:liveDomain -->` as in the template's `index.html`, `privacy-policy/index.html`, and `terms-of-service/index.html`. If `site.domain` is still `example.com`, set it to `""`.
4. **Run `npm run optimize-images`**, then `npm run build`.
5. **Owner, in Cloudflare:** turn on Web Analytics (project → Metrics → Enable), delete the `CF_ANALYTICS_TOKEN` variable, and move any keys out of the **Preview** environment (Production only).
6. **Owner, on GitHub:** making the repository **Public** publishes its whole history, not just today's files: every old version, every photo ever committed (with its GPS data, from before stripping existed), every note. Check the history first (`git log --stat`, and search old commits for photos and personal details). If anything private is in it, don't flip the switch: start a fresh public repository from the current, cleaned files instead, and reconnect Cloudflare to it. Otherwise: Settings → General → Danger Zone → Change visibility. Then add the ruleset and settings from `docs/setup-guide.md` Step 6.
7. **Retire staging:** after the upgrade ships, delete the `staging` branch. If the site had `staging.<domain>`, remove it from the project's Custom domains and delete its DNS record.

## Moving a Pages site to Workers (Phase 1, late 2026)

Sites set up before Phase 1 run on Cloudflare Pages, with a Resend key for the contact form. They keep working; move when the owner wants the keyless contact form. Background and the live checklist: [phase-1-plan.md](phase-1-plan.md). **If the domain's DNS is not on Cloudflare, don't move:** Workers can't attach that domain. Keep the site on Pages (the template's `docs/keep-your-dns.md`), with the contact form off.

1. **One pull request** with the Phase 1 machinery from `template/`: `wrangler.jsonc` (set `"name"` to a short site name), `src/worker.ts`, `.dev.vars.example`, `.gitignore`, `public/_headers`, `public/_redirects`, `scripts/`, `tsconfig.json`, `package.json` + `package-lock.json` (adds `wrangler`), plus `AGENTS.md`, `SETUP.md`, `rules/`, `features/` and `docs/`. Delete `functions/`. Turn `contactForm` off in the same change (Pages can't run the new form). Ship it: Pages keeps serving the site and ignores `wrangler.jsonc`.
2. **Owner, in Cloudflare:** **Workers & Pages** → **Create application** → **Import a repository** → the same repository, project name exactly as in `wrangler.jsonc`, the suggested build and deploy commands. Then **Settings** → **Variables and Secrets** → add the secret `CONTACT_TO_EMAIL`.
3. **Check the new copy:** `npm run audit https://<name>.<account>.workers.dev`.
4. **Move the domain, outside business hours** (a few minutes of downtime): the domain → **DNS** → **Records** → delete the CNAME records pointing at `<project>.pages.dev` (the domain and `www`; a Worker can't take a name that already has a record), then the Pages project → **Custom domains** → remove both, then the Worker → **Settings** → **Domains & Routes** → **Add** → **Custom domain**, for both. Turn on **Always Use HTTPS**. Audit the domain.
5. **Email:** Email Routing on, the owner's inbox verified and equal to `CONTACT_TO_EMAIL`. Turn `contactForm` back on as a change, ship it, and send a test message from the live form. Then delete the Resend key in Resend and the Pages project's variables.
6. **Visitor stats:** Pages' one-click analytics doesn't follow the site. Cloudflare → **Web Analytics** → **Add a site** → the domain (automatic setup). Remove the old Pages site entry if it double counts.
7. **After a week of calm:** delete the Pages project, so only one copy ever builds.
